# Отчет по ML Pipeline для Cropwise API Data

## Обзор

Создан полный pipeline для построения ML-модели прогнозирования урожайности на основе данных Cropwise Operations API. Pipeline включает:
1. Извлечение данных из API (fields, crops, operations, NDVI, productivity estimates)
2. Feature engineering с расширенными NDVI и операционными фичами
3. Обучение трех моделей с cross-validation по годам

---

## 1. Структура фич в финальном датасете

### 1.1. FIELD_* (геометрия и координаты)
- `field_tillable_area` - обрабатываемая площадь поля (га)
- `field_calculated_area` - расчетная площадь поля (га)
- `field_lat` - широта центра поля
- `field_long` - долгота центра поля

### 1.2. CROP_* (культура, сезонность)
- `crop_name` - название культуры
- `crop_season_type` - тип сезона (озимые/яровые)

### 1.3. OPS_* (агрооперации)

**Количество операций:**
- `ops_count_total` - общее количество операций
- `ops_count_soil` - количество операций обработки почвы
- `ops_count_application` - количество операций внесения удобрений/СЗР
- `ops_count_harvesting` - количество операций уборки
- `ops_count_seeding` - количество операций посева
- `ops_count_tillage` - количество операций обработки почвы
- `ops_count_spraying` - количество операций опрыскивания

**NPK из application_mix_items:**
- `ops_npk_n_total` - суммарная норма внесения азота (кг/га)
- `ops_npk_p_total` - суммарная норма внесения фосфора (кг/га)
- `ops_npk_k_total` - суммарная норма внесения калия (кг/га)
- `ops_npk_total` - суммарная норма NPK (кг/га)

**Временные интервалы:**
- `ops_season_start` - дата начала сезона (первая операция)
- `ops_season_end` - дата окончания сезона (последняя операция)
- `ops_season_duration_days` - длительность сезона в днях
- `ops_days_seeding_to_harvest` - количество дней от посева до уборки

**Урожайность из операций:**
- `ops_yield_t_ha` - урожайность из операций уборки (т/га)

### 1.4. NDVI_* (спутниковые данные)

**Базовые статистики по сезону:**
- `ndvi_mean_season` - среднее NDVI по сезону
- `ndvi_max_season` - максимум NDVI по сезону
- `ndvi_min_season` - минимум NDVI по сезону
- `ndvi_std_season` - стандартное отклонение NDVI

**Агрегаты по фазам сезона (по датам):**
- `ndvi_early` - среднее NDVI в ранний период (0-33% сезона по датам)
- `ndvi_mid` - среднее NDVI в средний период (33-66% сезона по датам)
- `ndvi_late` - среднее NDVI в поздний период (66-100% сезона по датам)

**Тренд и динамика:**
- `ndvi_trend` - коэффициент линейного тренда (наклон регрессии по времени)
- `ndvi_green_period_days` - количество дней, когда NDVI > 0.4 (длина "зеленого периода")
- `ndvi_observations` - количество наблюдений NDVI за сезон

## 2. Агрегации NDVI

### 2.1. По сезону
- **Среднее**: `ndvi_mean_season` - среднее значение всех NDVI наблюдений за сезон
- **Максимум**: `ndvi_max_season` - максимальное значение NDVI за сезон
- **Минимум**: `ndvi_min_season` - минимальное значение NDVI за сезон
- **Стандартное отклонение**: `ndvi_std_season` - вариативность NDVI

### 2.2. По фазам сезона
Деление сезона на три равные части **по датам** (не по количеству наблюдений):
- **Ранний период (0-33%)**: `ndvi_early` - среднее NDVI в первую треть сезона
- **Средний период (33-66%)**: `ndvi_mid` - среднее NDVI во вторую треть сезона
- **Поздний период (66-100%)**: `ndvi_late` - среднее NDVI в последнюю треть сезона

### 2.3. По месяцам
Не реализовано напрямую, но можно вывести из дат в `ndvi_timeseries.csv`.

### 2.4. Дополнительные метрики
- **Тренд**: `ndvi_trend` - коэффициент наклона линейной регрессии NDVI по времени (положительный = рост, отрицательный = спад)
- **Зеленый период**: `ndvi_green_period_days` - количество дней с NDVI > 0.4 (индикатор активной вегетации)

## 3. Признаки из operations.csv

### 3.1. Количество операций по типам
Реализовано через `operation_type`:
- `ops_count_soil` - обработка почвы
- `ops_count_application` - внесение удобрений/СЗР
- `ops_count_harvesting` - уборка
- `ops_count_seeding` - посев
- `ops_count_tillage` - обработка почвы
- `ops_count_spraying` - опрыскивание

### 3.2. NPK из application_mix_items
Реализовано через парсинг JSON строки `application_mix_items`:
- Извлекаются записи с `applicable_type == 'Fertilizer'`
- Суммируются `fact_rate` или `planned_rate` для каждого удобрения
- **Примечание**: В текущей реализации используется упрощенная логика (30% N, 10% P, 10% K). В продакшене нужно использовать справочник удобрений для точного маппинга NPK.

### 3.3. Временные интервалы
- `ops_days_seeding_to_harvest` - количество дней от посева до уборки
- `ops_season_duration_days` - общая длительность сезона

### 3.4. Дополнительные фичи
- `ops_yield_t_ha` - урожайность из операций уборки (если доступна)

## 5. Структура моделей

### 5.1. Модель №1: Без NDVI
**Фичи:**
- Все `field_*` фичи
- Все `crop_*` фичи
- Все `ops_*` фичи
- Другие не-NDVI фичи

**Цель:** Оценить вклад агроопераций и геометрии без спутниковых данных.

### 5.2. Модель №2: Только NDVI
**Фичи:**
- Только `ndvi_*` фичи

**Цель:** Оценить вклад спутниковых данных отдельно.

### 5.3. Модель №3: Все признаки вместе
**Фичи:**
- Все фичи из модели №1 + все фичи из модели №2

**Цель:** Полная модель с максимальным набором признаков.

---

## 6. Метрики и валидация

### 6.1. Метрики
- **R²** (коэффициент детерминации)
- **RMSE** (Root Mean Squared Error, т/га)
- **MAE** (Mean Absolute Error, т/га)
- **MAPE** (Mean Absolute Percentage Error, %)

### 6.2. Cross-validation
- **Метод:** GroupKFold по годам (leave-one-year-out style)
- **Folds:** 5
- **Группировка:** По полю `year` - гарантирует, что данные одного года не попадут одновременно в train и test

### 6.3. Сравнение моделей
Создается таблица сравнения всех трех моделей с метриками:
- CV R², RMSE, MAE, MAPE (среднее ± стандартное отклонение)
- Train R², RMSE, MAE, MAPE

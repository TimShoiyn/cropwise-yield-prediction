# Словарь признаков (Crop-window v1) — что значит каждый показатель и зачем он модели

Файл относится к датасету:

- `data_processed/ml_dataset_full_extended_cropwindow_v1_may_sep_oct.csv`

Единица наблюдения: **одно поле в один год** (`field_id × year`).

Таргет: **`target_yield_t_ha`** (тонн/га).

Важно:
- Для `wheat_spring` сезонное окно: **май–сентябрь (5–9)**.
- Для `sunflower` сезонное окно: **май–октябрь (5–10)**.
- Для остальных культур используется дефолтное окно **май–октябрь**.

Примечание про модель:
- В `train_baseline_model.py` признаки берутся как **числовые** (numeric) и пропуски заполняются **внутри Pipeline** (без утечки).
- Любые признаки, где **100% NaN**, автоматически удаляются перед обучением (например, `field_soil_CEC`, `field_soil_Ca_saturation`).

---

## 1) Ключи и целевая переменная

### `field_id`
- **Что это**: ID поля в Cropwise.
- **Роль**: ключ, чтобы объединять источники; **в модель как признак не должен идти** (иначе модель может “запомнить” поле).
- **В модели**: исключается (служебная колонка).

### `year`
- **Что это**: год сезона.
- **Роль**: используется как **группа** в GroupKFold (честная валидация по годам).
- **В модели**: обычно исключается как служебный ключ (в твоём коде `year` исключён из X).

### `target_yield_t_ha`
- **Что это**: урожайность (тонн/га) для этого поля и года.
- **Откуда**: из собранного таргета Cropwise (подробно см. `reports/DATA_LINEAGE.md`).
- **Роль**: целевая переменная (то, что прогнозируем).

---

## 2) Культура и предшественник (crop rotation)

### `crop_id`
- **Что это**: ID культуры в Cropwise для данного `field_id × year`.
- **Единицы**: нет (категория, код).
- **Как влияет**: разные культуры имеют разный потенциал урожайности → это один из самых сильных факторов.
- **Подводные камни**:
  - Это числовой ID, но по смыслу категория. В бустинге он всё равно работает, но может давать “ступеньки”.
  - Если в будущих данных появятся новые `crop_id`, модель не “знает” их — поэтому важна стабильность справочника `crops.csv`.

### `prev_crop_id`
- **Что это**: ID культуры‑предшественника (что было на поле в предыдущем году).
- **Зачем**: предшественник влияет на почву, сорняки, питание, влагу, технологию.
- **Ожидаемое влияние**: “хорошие” предшественники обычно повышают урожай (например, бобовые), “плохие” могут снижать.
- **Подводные камни**:
  - Может быть NaN, если нет истории для `year-1`.
  - Часто коррелирует с `crop_id` (севооборот), поэтому отдельный эффект может быть неочевиден.

---

## 3) Геометрия/координаты поля (устойчивые факторы)

Эти признаки не меняются по годам (или меняются слабо), но помогают модели “узнать” разные поля и локации.

### `field_tillable_area`
- **Что это**: обрабатываемая площадь поля (обычно га).
- **Почему важно**: косвенно отражает крупность/контуры, особенности менеджмента; иногда влияет через точность учёта.
- **Подводные камни**: может коррелировать с `field_calculated_area`.

### `field_calculated_area`
- **Что это**: площадь, рассчитанная по геометрии контура (обычно га).
- **Зачем**: контроль качества площади, иногда отличается от tillable_area.

### `field_lat`, `field_long`
- **Что это**: координаты центра поля.
- **Зачем**:
  - фиксируют региональные градиенты (климат/почва/осадки);
  - помогают “разделить” разные хозяйства/кластеры полей.
- **Подводные камни**:
  - если полей мало и они в одном районе, вклад будет меньше;
  - если модель начнёт “привязываться” к координатам, переносимость на другие регионы ограничена.

## 4) NDVI (состояние растительности по спутнику) — внутри сезонного окна культуры

NDVI ≈ индекс “зелёности/биомассы”. Для урожайности NDVI обычно один из самых информативных сигналов, потому что отражает фактическое развитие посева.

### `ndvi_observations`
- **Что это**: число наблюдений NDVI в сезонном окне.
- **Зачем**:
  - это прокси качества данных: чем меньше наблюдений, тем менее устойчивы агрегаты.
- **Как влияет**: обычно напрямую не “про урожай”, но помогает модели учитывать надёжность.
- **Подводные камни**: может коррелировать с облачностью/годом/сезоном.

### `ndvi_mean_season`
- **Что это**: средний NDVI в сезонном окне культуры.
- **Интуиция**: “в среднем насколько посев был развит/зелёный” за сезон.
- **Ожидаемое влияние**: чаще **положительное** (выше средний NDVI → выше урожай).
- **Подводные камни**:
  - среднее сглаживает пики: два поля с одинаковым средним могут иметь разную динамику.

### `ndvi_max_season`
- **Что это**: максимальный NDVI в сезонном окне.
- **Интуиция**: пик биомассы/покрытия.
- **Ожидаемое влияние**: чаще **положительное**.
- **Подводные камни**:
  - иногда максимум ловит шум/артефакт (редко, но бывает).

### `ndvi_early`, `ndvi_mid`, `ndvi_late`
- **Что это**: средний NDVI в ранней/средней/поздней части сезонного окна.
- **Как считается**: точки NDVI сортируются по дате, делятся на 3 группы (примерно равные по количеству), берётся среднее в каждой.
- **Зачем**:
  - ранний NDVI ≈ старт и всходы;
  - mid NDVI ≈ активная вегетация;
  - late NDVI ≈ налив/созревание/деградация зелёной массы.
- **Ожидаемые эффекты**:
  - низкий `ndvi_early` может означать поздний посев/плохие всходы → снижение урожая;
  - высокий `ndvi_mid` часто хорошо коррелирует с урожайностью;
  - `ndvi_late` может быть двояким: высокая “зелёность” в конце может означать позднее созревание/сорт, но может и отражать отсутствие стресса.
- **Подводные камни**:
  - если `ndvi_observations` мало, деление на 3 части становится шумным.

## 5) Почва (последний Soil Test на поле) — “фоновые” факторы

Это относительно стабильные показатели, которые объясняют часть различий между полями, но обычно слабее NDVI/погоды по межгодовой вариативности.

### `field_soil_pH`
- **Что это**: кислотность почвы (обычно pH 0–14).
- **Как влияет**: экстремально низкий/высокий pH ухудшает усвоение питания → снижение урожая.
- **Подводные камни**: часто тестов мало → пропуски.

### `field_soil_OM`
- **Что это**: органическое вещество (обычно %).
- **Интуиция**: плодородие/структура/влагоёмкость.
- **Ожидаемое влияние**: чаще **положительное**.

### `field_soil_P`, `field_soil_K`, `field_soil_N`, `field_soil_N_NO3`
- **Что это**: обеспеченность фосфором/калием/азотом (и/или нитратным азотом).
- **Единицы**: зависят от лаборатории (могут быть мг/кг, ppm, и т.п.) — модель работает с числами как есть.
- **Как влияет**: дефициты → снижение урожая; избытки/ошибки измерений могут давать шум.
- **Подводные камни**:
  - разные методики лабораторий и годы отбора → возможная несопоставимость.
  - `field_soil_N` и `field_soil_N_NO3` могут быть сильно связаны.

### `field_soil_Mg`
- **Что это**: магний (важен для фотосинтеза).
- **Ожидаемое влияние**: чаще положительное в диапазоне дефицита.

### `field_soil_CEC`, `field_soil_Ca_saturation`
- **Что это**: ёмкость катионного обмена / насыщенность Ca.
- **Статус сейчас**: в твоём датасете **100% NaN** (по sanity: 441/441).
- **Как используется**: автоматически дропается перед обучением, чтобы не мешать.
- **Что сказать преподавателю**: “в данных Cropwise эти показатели в выгрузке отсутствуют, поэтому мы их исключаем”.

## 6) Погода (daily → агрегаты) — внутри сезонного окна культуры

Погода объясняет межгодовую вариативность: один и тот же участок может сильно отличаться по урожаю в разные годы из‑за температуры/осадков/жары.

### `weather_temp_avg_season`
- **Что это**: средняя температура за сезонное окно (°C).
- **Как влияет**: зависит от культуры: слишком холодно/жарко ухудшает; в умеренном диапазоне может улучшать.

### `weather_gdd_season`
- **Что это**: Growing Degree Days — сумма “активных температур” за сезон.
- **Как считается**: по дням суммируется `max(temp_avg - base_temp, 0)`, где base_temp зависит от культуры (в `build_ml_dataset.py`).
- **Интуиция**: “сколько тепла накопилось”, влияет на развитие и фазу созревания.

### `weather_precip_sum_season`
- **Что это**: сумма осадков за сезонное окно (обычно мм).
- **Ожидаемое влияние**: чаще положительное в условиях дефицита влаги, но может быть нелинейность (переувлажнение тоже плохо).

### `weather_precip_sum_early`
- **Что это**: сумма осадков в первой половине сезонного окна.
- **Зачем**: ранняя влага критична для стартового развития/корневой.

### `weather_hot_days`
- **Что это**: число дней в сезонном окне с `temp_max > 30°C`.
- **Интуиция**: тепловой стресс → часто снижает урожай.

### Подводные камни по погоде (важно для НИРД)
- В sanity‑проверке видно долю строк, где **все weather_* = NaN**:
  - all: ~0.186
  - sunflower: ~0.287
  - wheat: 0.000
- Это влияет на качество: когда погоды нет, модель опирается на NDVI/геометрию/культуру.

## 7) “Как признаки влияют на предсказание” (как объяснить без SHAP)

Твой алгоритм — градиентный бустинг по деревьям. Он работает так:
- находит разбиения вида “если `ndvi_max_season > X`, то прогноз +Δ”
- комбинирует много маленьких правил

Общий смысл влияний (что обычно ожидают услышать):

- **NDVI (особенно `ndvi_max_season`, `ndvi_mid`)**: главный сигнал состояния посевов → часто главный вклад в прогноз.
- **Погода (`precip_sum_*`, `gdd`, `hot_days`)**: объясняет “почему этот год хуже/лучше” при похожих полях.
- **Почва**: задаёт “фон” плодородия, но меняется медленно.
- **crop_id / prev_crop_id**: фиксируют различия культур и севооборота.

Если преподаватель спросит “покажи, что важнее”:
- в проекте есть графики feature importance (для соответствующих запусков) в `models/feature_importance_*.png`.

- в `reports/debug/target_by_year_wheat.csv` есть годы с **n=2–3** → метрики по годам “скачут”.

## 9) Как это вставлять в презентацию (совет)

1) Слайд “Что на входе модели”:
- кратко блоками (геометрия / культура / NDVI / погода / почва)
- 1–2 примера расшифровки (например `ndvi_mean_season`, `weather_gdd_season`)
- обязательно: “окно зависит от культуры”

2) Слайд “Почему wheat R² отрицательный”:
- показать `N=67` и “по годам есть n=2–3”
- сказать: “поэтому R² нестабилен, ориентируемся на RMSE/MAPE и просим больше данных”

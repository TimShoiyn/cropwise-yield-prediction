# Microscope audit — final conclusions

Generated by `scripts/audit/microscope_audit.py` and `scripts/audit/microscope_final_summary.py`.

## TL;DR

1. **Critical leakage bug found**: `cropwise_asof_t_ha` was a feature in every model from v9 onward (it was never on the non-feature list). With it removed, all-crops 1 Sep flipped from ML-win to Cropwise-win, wheat 1 Sep moved to Cropwise, and feature importance no longer puts the Cropwise estimate as the #1 feature.
2. **Sunflower results were noise**: the naive `last_year` baseline reaches 23.9% MAPE on the same rows where ML gets 25-26%. There is no real signal for sunflower at this dataset size.
3. **Wheat ML is real signal**: the same naive baselines sit at 40-62% MAPE while ML stays at 28-34%. ML beats them on R^2 too. So the wheat numbers are not a fluke.
4. **All-crops ML beats naive but not Cropwise on R^2**: ML stays at around 28-31% MAPE vs naive 34-47%, but R^2 stays close to 0 while Cropwise is at 0.25-0.34. ML predicts close to the train-year mean and only marginally ranks fields.
5. **Severe overfitting on a tiny dataset**: in-sample R^2 = 0.94-0.99 on the same data where OOF R^2 is around 0. This is the bottleneck: 127-180 rows is not enough to train CatBoost without memorizing.

## 7. What this means for the dissertation narrative

Honest framing for the paper:

- The most important methodological contribution is the multi-stage data-quality pipeline: factual target reconstruction (v7), unit-error fix from a Russian legacy sheet (v12), conflict-clean sensitivity (v16), and strict cross-source target priority (v17). Each step has a measurable effect on metrics.
- The Cropwise-leak bug is itself a finding: any prior published comparison that uses the platform's own real-time estimate as a feature is overstating ML performance.
- ML beats Cropwise on `all_crops` and `wheat` MAPE only at 1 Jul / 1 Aug. By 1 Sep Cropwise narrows the gap or wins. This is consistent with Cropwise getting more in-season signal closer to harvest.
- Cropwise wins on R^2 / MAE / RMSE everywhere except sunflower at 1 Jul. ML ranking ability is weak because the dataset is tiny (n_train ≤ 100 in walk-forward folds).
- Sunflower numbers should not be claimed as ML beats Cropwise: the naive last-year baseline is at the same level as ML, so the difference vs Cropwise on sunflower is statistical noise.

## 8. Decision tree for next step

Three options, ranked by effort:

1. **Stop here, write up honestly.** Frame the paper around the data-quality pipeline and the Cropwise-leak finding. Report MAPE/MAE/RMSE/R^2 side by side, claim ML wins MAPE at 1 Jul/1 Aug for `all_crops` and `wheat`, do not claim ranking superiority. This is publishable as-is.
2. **Expand the data first.** The bottleneck is n=127. Three concrete ways to grow it:
   a) Fetch geometry + NDVI for the remaining ~507 fields via Open Platform with a fresh API token (the cheapest big win).
   b) Hand-map field coordinates from the user's farm records and pull NDVI from Sentinel-2 / MOD13Q1 directly.
   c) Pool with neighboring farms in the same VKO region if a partner provides data.
3. **Improve the model on the current dataset.** Diminishing returns, but worth a try:
   - Add NDRE / EVI to compensate for NDVI saturation in dense wheat canopies.
   - Use blend regression: predict `target - crop_mean` as residual on top of a crop-mean prior. This often helps small datasets generalize.
   - Try LightGBM with monotonic constraints on agronomic features.
   - Hyperparameter sweep with explicit early-stopping on a held-out year, not random 20% (current setup is leaky inside the train fold).

# Roadmap: как обойти Cropwise (план до результата)

Цель диссертации: **стабильно прогнозировать урожайность лучше Cropwise**, честно
(без использования прогноза Cropwise как признака), на наших реальных полях.

Где мы сейчас (после v24):
- сняли data bottleneck — реальные **483 поля / 1903 field-year**, 2017-2025;
- починили влажность почвы, добавили GDD/heat-stress;
- **подсолнечник 1 июля/августа: v24 уже бьёт Cropwise** (MAPE и ранжирование);
- пшеница и all_crops: Cropwise ещё держит MAPE/pooled R², но v24 лучше по
  честному ранжированию полей (within-crop-year R²);
- поздний сезон (1 сен) — слабое место против Cropwise.

Главная гипотеза плана: **бьём Cropwise не «ещё одним CatBoost», а правильными
признаками (red-edge/EVI, влага, фенология, менеджмент) + crop-specific
калибровкой + чистой целью.**

## Этап A. Чистка и фундамент (быстро, высокий приоритет)

### A1. Target audit низкоурожайных строк [x]
- **Что**: разобрать все строки `target < 1 т/га` — это пересев/гибель/ошибка, а не «плохой прогноз».
- **Зачем**: они дают MAPE 100%+ и портят вывод по all_crops.
- **Как**: скрипт `scripts/audit/audit_low_yield_rows_v24.py` — по culture/year/field, target source, NDVI-профиль, Cropwise evidence.
- **Результат**: main-regression policy `target >= 1 т/га`; low-yield rows отдельно как target-quality/anomaly task.
- **Метрика успеха**: честный all_crops MAPE без артефактов.

### A2. Зафиксировать чистый feature-контракт v24 [x]
- **Что**: явный список core-признаков по культуре (NDVI core + влага + GDD + heat + soil P/OM + sowing).
- **Зачем**: 82 колонки, часть дублируется (p25/p75/mean/integral сильно коррелируют).
- **Как**: агро-прунинг + walk-forward проверка `v24_pruned`.
- **Результат**: `scripts/asof/feature_sets_v24.py`; full/pruned режим выбирается per crop × as-of по валидации.

## Этап B. Новые данные (главный рычаг качества)

### B1. Sentinel-2 red-edge/EVI/GCVI по геометрии полей [ ]
- **Что**: вытащить NDRE, EVI, GCVI (и при желании NDWI) по geojson 640 полей.
- **Зачем**: литература прямо говорит — red-edge/EVI бьют NDVI на плотном пологе
  (насыщение NDVI), особенно пшеница в фазе налива. В Cropwise API этих индексов НЕТ.
- **Как**: Google Earth Engine (Sentinel-2 L2A, 2017-2025) по `shape_simplified_geojson`,
  агрегаты по полю и дате → тот же as-of формат, что NDVI.
- **Риск**: GEE-доступ/квоты; объём выгрузки.
- **Результат**: `data_raw/s2_indices_*.csv`, фичи `ndre_*`, `evi_*`, `gcvi_*`.
- **Метрика успеха**: рост сигнала по пшенице на пике сезона, лучше late-season.

### B2. Менеджмент-признаки (особенно фосфор) [ ]
- **Что**: пере-привязать удобрения/нормы/обработки (v13-v15) к v24.
- **Зачем**: для подсолнечника P лимитирует урожай (подтвердили данными: P corr +0.20).
- **Как**: agro_operations + seed/fertilizer rates → as-of (только до даты прогноза).
- **Результат**: `mgmt_*` фичи, отдельно `fert_P_rate`.

### B3. Per-field осадки [ ]
- **Что**: добавить осадки на уровне поля (не грид Open-Meteo).
- **Зачем**: гридовая погода слабо работает на уровне поля (литература).
- **Как**: из того же S2/спутникового стека или CHIRPS по геометрии.

## Этап C. Моделирование (после того как данные готовы)

### C1. Crop-specific финальные модели v25 [ ]
- **Что**: отдельные модели wheat / sunflower на расширенном наборе (B1-B3).
- **Зачем**: разные фенология/драйверы; общая модель усредняет.
- **Как**: CatBoost + walk-forward, low-yield-filter из A1, feature sets из A2.
- **Результат**: `evaluate_v25_*`.

### C2. Late-season калибровка (1 сен) [ ]
- **Что**: разобраться, почему Cropwise силён на 1 сентября, и закрыть разрыв.
- **Зачем**: сейчас единственное окно, где Cropwise уверенно лучше.
- **Как**: добавить поздне-сезонные признаки (накопленный integral до сен, спад NDVI),
  возможно отдельная модель на 1 сен.

### C3. Quantile/uncertainty [ ]
- **Что**: прогноз с интервалом (P10/P50/P90), а не точкой.
- **Зачем**: для диссертации и практики честнее, чем одно число.
- **Как**: CatBoost quantile loss или ансамбль.

## Порядок исполнения (рекомендация)

1. **A1 + A2** — день, чистим фундамент, сразу честнее метрики.
2. **B1** — главный рычаг (red-edge). Делать первым из «данных».

подсолнечнике хотя бы для 2 из 3 as-of дат, честно и воспроизводимо.**

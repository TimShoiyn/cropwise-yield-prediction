## Главная находка

Раньше фактический урожай (ground-truth) был только на **30 полях**. Теперь:

- **`agro_operations` с `operation_type=harvesting`** дают фактический урожай через
  `harvested_weight (т) / completed_area (га)` → **528 полей, 1499 пар field-year (2021–2025)**.
- **`yield_maps`** дают независимую оценку с комбайна по сетке → 90 полей.

Это снимает главное узкое место всего проекта (мало ground-truth).

### Решения по чистке
- **Единицы:** `estimate_value` хранится в **ц/га**, фактический урожай — в **т/га**. Конверсия `/10`. Проверено: медианное отношение estimate/harvest = 9.9 ≈ 10.
- **Фильтр урожая:** оставлены только реалистичные значения 0.1–16 т/га (отсев unit-шума).
- **Дедуп:** на (field_id, year) берётся уборка с наибольшей `completed_area` (основная уборка поля).

## Что НЕ нашлось / ограничения
- NDRE/EVI/GCVI в API нет → берём из Sentinel-2 (этап B1, идёт в фоне).
- В `agro_operations` нет прямого `crop_id` — культуру надо матчить через `crops` + история поля.
- `marketable_weight` почти пустой (60 строк) — используем `harvested_weight`.
